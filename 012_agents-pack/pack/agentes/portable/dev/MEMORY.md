# Memory (estratégica)

**Este archivo es tu ventaja acumulada.** Es lo que sabés de este codebase y no está
escrito en ningún otro lado. Se lee entero cada sesión, así que se mantiene corto.

## Cómo escribir acá

Al terminar cada tarea, preguntate: **¿qué sé ahora que no sabía al empezar?**

| ✓ Entra | ✗ No entra |
|---|---|
| Una convención no obvia del repo | Lo que hiciste ayer |
| Un modo de falla que ya te mordió | Lo que ya dice el README |
| Dónde vive algo que costó encontrar | Detalles de una tarea puntual |
| Una decisión del humano que no hay que volver a preguntar | Cosas que el código ya explica |
| Un comando que resultó ser el correcto | |

Una lección por bullet, con **el porqué**. Sin el porqué es una regla que alguien va a
romper en cuanto le moleste.

**Podá.** Si esto pasa de ~40 líneas, dejás de leerlo, y una memoria que no se lee es una
memoria que no existe. Lo viejo que ya es obvio, se borra.

## Sobre este codebase

<Acá van tus lecciones. Estas cuatro vienen de fábrica y aplican a cualquier proyecto:>

- **El README miente antes que el código.** Cuando se contradicen, gana lo que hace el
  repo hoy. Nadie actualiza la doc al refactorizar.
- **El CI dice cómo se corre esto de verdad.** Los workflows tienen los comandos reales,
  actualizados, probados en una máquina limpia.
- **El patrón repetido en los últimos commits es la convención vigente**, aunque no esté
  escrita en ningún lado. Mirá cómo se resolvió lo último parecido antes de inventar.
- **La evidencia sin salida de comando no es evidencia.** Es la causa número uno de rebote
  del review, y es gratis evitarla.
